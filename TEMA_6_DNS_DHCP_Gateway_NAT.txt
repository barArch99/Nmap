                                         TERCERA CLASE
                          TEMA 6: DNS, DHCP, GATEWAY Y NAT
       (Practica en BlackArch - host 'blackarch' - fecha: 2026-11-09 - estilo HTB: tasks)

==================================================================================================

   •   GATEWAY (puerta de enlace): la SALIDA de mi red hacia otras redes (internet).
       Casi siempre es el router. Todo paquete cuyo destino NO esta en mi red local se le
       entrega al gateway para que lo saque. En la tabla de rutas es la ruta "default".

   •   DNS (Domain Name System): traduce NOMBRES a IPs (como una agenda de contactos).
       Yo escribo scanme.nmap.org, pero la red solo entiende 45.33.32.156.
           - Puerto 53. Sobre todo UDP (consultas normales, rapidas, sin conexion).
             TCP 53 solo para respuestas grandes y TRANSFERENCIAS DE ZONA (copiar todos
             los registros de un dominio → muy usado en pentesting).
           - /etc/resolv.conf   → A QUE servidor DNS preguntar (linea "nameserver").
           - /etc/hosts         → "agenda manual" nombre → IP que se consulta ANTES del DNS
                                  (ahi esta 127.0.0.1 localhost y ahi se pone unika.htb en HTB).
           - Tipos de registro:
                 A      nombre → IPv4
                 AAAA   nombre → IPv6
                 PTR    IP → nombre (busqueda INVERSA)
                 MX     servidor de correo del dominio
                 NS     servidores DNS que mandan sobre el dominio
                 SOA    "quien manda" en la zona (autoridad)
           - NXDOMAIN = "Non-Existent Domain": ese nombre no existe.

   •   DHCP (Dynamic Host Configuration Protocol): cuando me conecto a la red no tengo
       IP, gateway ni DNS. Mi PC "grita" a la red pidiendo configuracion y el servidor
       DHCP (el router) me la PRESTA por un tiempo → eso se llama LEASE (prestamo).
           - Un solo prestamo entrega: IP + mascara, gateway, DNS y duracion.
           - A la MITAD del tiempo el PC pide RENOVAR (normalmente le dan la misma IP).
           - En Linux la IP prestada aparece como "dynamic"; puesta a mano = "permanent".

   •   NAT (Network Address Translation): mi IP privada (192.168.x.x) NO existe en
       internet (millones de casas tienen la misma). El router CAMBIA mi IP privada por
       SU IP PUBLICA al sacar el paquete, y al volver la respuesta la devuelve a mi PC.
           - Todos los equipos de la casa salen con la MISMA IP publica.
           - Nadie de afuera puede INICIAR una conexion a mi PC: el router no sabria a
             cual equipo mandarla (como la porteria de un edificio).
           - VirtualBox en modo NAT hace lo mismo con la VM (gateway virtual 10.0.2.2);
             en modo PUENTE (bridged) la VM es un equipo mas de la red (gateway 192.168.1.1).
           - En HTB la victima no ve mi IP de casa: ve mi IP de la VPN (tun0).

   •   COMO SE RELACIONA CON NMAP:
       - Sin -n, Nmap hace un DNS INVERSO (PTR) por cada IP que escanea (las lineas NSOCK
         del Tema 5). 256 IPs = 256 consultas → -n acelera y hace menos ruido.
       - scanme.nmap.org es el servidor que Nmap AUTORIZA para practicar.
       - Desde fuera, un escaneo a mi IP publica choca con el ROUTER (NAT), no con mi PC.

   Practica y resultados propios (estilo HTB: pregunta → como lo encontre → respuesta)
   --------------------------------------------------------------------------------------------------
   Equipo: BlackArch por CABLE (enp8s0). Se hizo en mi propio equipo (sistema autorizado).

   Task 1) ¿Cual es la IP del gateway?
       ip route  → linea "default via ..."
       Respuesta: 192.168.1.1 (el router de la casa)

   Task 2) ¿El gateway responde?
       ping -c 5 192.168.1.1

       64 bytes from 192.168.1.1: icmp_seq=1 ttl=64 time=4.31 ms
       ...
       5 packets transmitted, 5 received, 0% packet loss, time 4004ms
       rtt min/avg/max/mdev = 4.305/4.442/4.630/0.115 ms

       - -c 5 = mandar solo 5 paquetes (si no, sigue para siempre).
       - 5 enviados, 5 recibidos, 0% perdidos. Promedio (avg) 4.442 ms.
       - ttl=64 → Linux suele empezar en 64 (Windows en 128): el router corre Linux por dentro.
       - ~4 ms es normal en la misma red; un sitio de internet suele tardar 20 ms o mas.

   Task 3) ¿Cual es la IP del servidor DNS?
       cat /etc/resolv.conf

       # Generated by NetworkManager
       nameserver 200.21.200.10
       nameserver 200.21.200.80

       - Dos DNS: el primero y uno de RESPALDO si el primero no responde.
       - Son IPs PUBLICAS → DNS del proveedor de internet (los mismos del Tema 5).
       - Lo genera NetworkManager → no editarlo a mano (lo reescribe).
       - Error mio: primero respondi 127.0.0.1 porque lei /etc/hosts (localhost), que es
         otro archivo. Comprobado con sudo ss -tulnp: NO hay nada escuchando en el puerto
         53 de mi equipo, asi que no hay DNS local.
       - Error mio 2: corri "sudo ss -tulnp" y "grep :53" por separado; sin el | (pipe)
         grep se queda esperando texto. Correcto: sudo ss -tulnp | grep :53

   Task 4) ¿Que IP tiene scanme.nmap.org y que servidor respondio?
       Primer intento con typo: dig scanme.namp.org
           status: NXDOMAIN, ANSWER: 0   → ese nombre NO existe
           AUTHORITY SECTION: namp.org. 600 IN SOA ns11.domaincontrol.com. ...
           → el dominio namp.org si existe y responde quien manda (registro SOA)
           Query time: 209 msec  (vs ~4 ms del router: el DNS esta en internet)

       Correcto: dig scanme.nmap.org
           scanme.nmap.org.   3600   IN   A   45.33.32.156
                 │             │     │    │        │
              nombre          TTL  clase tipo     IP
           SERVER: 200.21.200.10#53(200.21.200.10) (UDP)

       - Respuesta: 45.33.32.156, respondio 200.21.200.10 por el puerto 53 UDP.
       - TTL del DNS = SEGUNDOS que se puede guardar en cache la respuesta.
         (NO es el TTL del ping, que cuenta saltos entre routers.)
       - IN = Internet. A = nombre → IPv4.
       - dig viene en el paquete "bind" en Arch.

   Task 5) DNS inverso: ¿que nombre tiene 45.33.32.156?
       dig -x 45.33.32.156

       ;156.32.33.45.in-addr.arpa.    IN    PTR
       156.32.33.45.in-addr.arpa. 300  IN  PTR  scanme.nmap.org.

       - -x = reverse. Registro PTR: 45.33.32.156 → scanme.nmap.org.
       - La IP va AL REVES + .in-addr.arpa: asi guarda el DNS las busquedas inversas.
       - Esta es la misma consulta que hace Nmap por cada IP si no se usa -n.

   Task 6) DHCP: ¿que IP me prestaron, quien y por cuanto tiempo?
       nmcli device show enp8s0 | grep DHCP4   → no mostro nada (mi NetworkManager no
                                                  enseña esa seccion)
       nmcli device show enp8s0
           IP4.ADDRESS[1]:  192.168.1.20/24
           IP4.GATEWAY:     192.168.1.1
           IP4.DNS[1]:      200.21.200.10
           IP4.DNS[2]:      200.21.200.80
           IP4.WINS[1]:     192.168.1.1
       nmcli -f ipv4.method connection show "Wired connection 1"  → ipv4.method: auto

       ip -4 addr show enp8s0
           inet 192.168.1.20/24 brd 192.168.1.255 scope global dynamic noprefixroute enp8s0
              valid_lft 80874sec preferred_lft 80874sec

       - IP: 192.168.1.20/24 (privada; mascara 255.255.255.0 → red .1 a .254).
       - "auto" y "dynamic" = la IP la presto el DHCP (no puesta a mano).
       - Servidor DHCP: el router 192.168.1.1 (de ahi salen gateway, DNS y WINS).
       - valid_lft 80874 s ÷ 3600 = ~22,5 h RESTANTES (el prestamo seguramente es de
         24 h = 86400 s y ya habia pasado hora y media).

       Todo lo que entrego el router en un solo prestamo:
           IP + mascara   192.168.1.20/24
           Gateway        192.168.1.1
           DNS            200.21.200.10 y 200.21.200.80
           Duracion       ~24 h

   Task 7) NAT: ¿con que IP me ve internet?
       wget -qO- ifconfig.me

       Prepended http:// to 'ifconfig.me'
       190.xxx.xxx.xxx%        ← IP PUBLICA CENSURADA

       - -q = silencioso, -O- = sacar el resultado a la pantalla (curl tambien sirve).
       - El % final NO es de la IP: zsh avisa que la respuesta no termino en salto de linea.
       - Mi IP publica no se parece en nada a 192.168.1.20 → el router hace NAT:

           Mi PC                    Router (NAT)                    Internet
           192.168.1.20  ──────►  cambia el origen a  ──────►  ifconfig.me ve:
           (privada)              la IP publica                "me habla la IP publica"
                         ◄──────  y devuelve la        ◄──────
                                  respuesta a .20

       - La IP publica NO se pone en repos publicos ni se comparte.

   --------------------------------------------------------------------------------------------------
   Conclusiones del Tema 6
   --------------------------------------------------------------------------------------------------
       - Gateway = salida de la red (ruta "default" en ip route). El mio: 192.168.1.1.
       - DNS = nombres → IPs, puerto 53 (UDP normal, TCP para zonas/respuestas grandes).
         /etc/resolv.conf dice a quien preguntar; /etc/hosts es la agenda manual.
       - dig: ANSWER (respuesta), SERVER (quien respondio), status (NOERROR / NXDOMAIN).
         Registros A (nombre → IP) y PTR (IP → nombre, con dig -x).
       - Nmap hace PTR por cada IP → -n lo desactiva (mas rapido, menos ruido).
       - DHCP = el router PRESTA IP, mascara, gateway y DNS por un tiempo (lease).
         "dynamic" + valid_lft en ip addr.
       - NAT = el router cambia mi IP privada por su IP publica; desde afuera nadie puede
         iniciar conexion a mi PC sin pasar por el router.
       - Siempre usar | para encadenar comandos (ss | grep) y revisar typos (namp → NXDOMAIN).
